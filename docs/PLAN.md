# t-alent：可编程 Harness 框架初步计划

日期：2026-10-01。阶段：独立前端、通用本地包宿主、DeepSeek 原版 Harness 包，以及 Codex 官方 App Server 适配包已接入。组合 SDK、Codex Rust 内部模块拆分和完整双真实包验收仍未完成。

当前执行顺序按用户后续要求调整：先迁移独立前端，再将原版 DeepSeek Harness 做成可选择的 Agent 包。前端来源记录在 `apps/web/MIGRATION.md`。`packages/runtime` 通过显式本地路径装载包代码，提供任务事件、取消和卸载；框架没有默认 Agent。`packs/deepseek` 固定依赖官方 `@deepseek-ai/dsh@0.2.0-rc.2`，运行原版 headless profile，保留其执行循环、模型适配、工具和持久会话。包支持模型参数和有序 Cordis patch 定制；这尚不等于下文规划的通用 `harness.ts` 组合 SDK。`packs/codex` 固定依赖官方 `@openai/codex@0.159.3`，通过官方 App Server 做原版 Harness 的 stdio 适配；它提供边界级集成，不表示可以任意替换 Codex Rust 执行循环内部源码模块。

已用本地 Messages API 模拟服务驱动实际原版 DeepSeek Harness，验证工具读取、持久历史续跑、取消后恢复和提供方错误。Codex 包同样用实际官方运行时连接本地 Responses API 模拟服务，验证原版 shell 读取与工具结果回传、多轮及跨实例历史恢复、取消续跑和错误传递；工作区代码程序改变模型输入的能力也已验证。尚未调用真实 DeepSeek 或 Codex 模型 API；使用者需在宿主环境设置相应密钥。独立包说明分别见 `packs/deepseek/README.md` 和 `packs/codex/README.md`，`Reference/` 保持本地参考源码并排除上传。

2026-10-02 更新：前端补充由当前 Agent 包提供的模型目录、包默认模型与自定义 ID 选择。宿主将可选的任务模型字段传给包；两个原版适配包将其写入各自的 Harness 配置。切换模型创建新会话，运行中不可切换。此功能属于模型参数控制，不表示组合 SDK 或内部循环替换已完成。

## 1. 产品目标

项目名称为 `t-alent`。创建一个独立的 Agent 运行与组合框架。框架提供装载、组装和运行 Agent 包的能力，本身不提供可执行的内置 Agent。执行任何模型/Agent 任务都必须先选择并加载 Agent 包；未加载包时，宿主仅允许管理包和设置，不得进行推理、运行工具或自动回退到内置 Agent。用户选择 Agent 包后，获得该包提供的 Harness 默认行为；用户还可以用代码替换其中的能力模块，组成自己的 Harness。

本项目中的 Agent 包是独立分发的可执行能力组合，可以携带代码，包含执行循环、提示词构建、模型适配、工具、上下文管理和会话策略。包通过框架 SDK 控制模型的调用方式及外部行为，例如循环与上下文、提示词、请求/响应中间件、工具和结果校验、重试、终止与模型路由。框架与参考 Agent 包分别分发；框架可以独立交付，但运行任务必须安装并加载包。Codex 与 DeepSeek 包是参考包，也是框架兼容性验收载体。首版界面仅用于选包、配置、输入任务、查看事件和处理交互。

选择包与选择模型分开：包决定如何使用模型和工具，模型决定本次推理的提供方与具体型号。包声明支持的模型协议和能力；仅更换模型名称不能保证兼容或同等效果。

## 2. 基本结构

```text
命令行 / 后续界面
        ↓
宿主：包管理、项目与会话入口、运行环境、事件交互
        ↓
组合内核：依赖解析、作用域、模块生命周期、事件与资源清理
        ↓
Agent 包默认组合 + 用户的 TypeScript 组合程序
        ↓
执行循环 / 上下文 / 模型 / 提示词 / 工具 / 调度 / 会话存储
```

关键约束：框架不内置 Agent 循环、可运行的默认 Agent 或 GPT/DeepSeek 请求策略。文档中所称“默认包”或“默认循环”，均指用户所选 Agent 包提供的默认包组合或循环，不是框架内置能力。替换 Agent 包后，宿主不需要修改源码；没有包时也不能隐式调用其他 Agent。

| 层级 | 拥有的职责 |
| --- | --- |
| 组合内核 | 加载依赖、注册服务、建立实例作用域、管理生命周期、分发扩展事件、释放资源 |
| 宿主与基础服务 | 包版本与锁定、启动停止、工作区、交互通道、日志入口、凭据引用、受约束的文件和进程运行环境 |
| Agent 包 | 循环、模型协议适配、提示词、工具的模型可见定义和行为、上下文选择与压缩、终止与重试、子 Agent 编排、状态编码与恢复策略 |
| 用户组合程序 | 选择并加载 Agent 包、添加或替换模块、配置模型与参数、注册中间件、定义路由和工作流 |

文件系统和进程等基础服务的实现也允许替换；宿主约束它们可使用的资源。包提供策略，宿主执行用户授予的权限上限。进程隔离与操作系统沙箱分别定义，不能把“单独启动进程”当成权限隔离。

## 3. 可编程能力

主要入口计划为 `harness.ts`，普通配置用于常见参数；二者使用同一套组合 SDK。下列调用仅表达设计意图，尚不是已实现 API：

```ts
export default defineHarness(({ use, replace, middleware }) => {
  use(codexPack());
  replace('context.compactor', myCompactor());
  replace('tools.executor', myExecutor());
  middleware('model.request', myRequestPolicy());
});
```

首版必须能够：

1. 选择并加载一个完整 Agent 包，使用该包提供的默认组合运行任务；未加载包时拒绝任务提交，且宿主只开放包和设置管理能力。
2. 替换模型适配、工具或上下文模块，无需修改宿主或原包。
3. 替换整个执行循环，而非仅在固定循环前后加回调。
4. 在模型请求前后、工具执行前后、轮次开始和结束处注册有明确次序的中间件。
5. 为不同实例建立独立作用域，避免服务、工具、状态或监听器串到其他会话。
6. 导出最终组合与版本，记录每个能力的来源，便于复现和排查。

替换前校验模块接口版本和依赖。循环与上下文投影等紧密耦合的模块允许声明为一组共同替换，不能承诺任意模块自由混搭。首版组合变更在新实例或明确停止后的重建中生效；运行中的代码热替换放在后续阶段。

## 4. Agent 包与协议

包的描述文件至少记录：包标识、版本、内核兼容版本、入口、能力清单、包提供的默认组合、依赖、配置定义、状态格式版本、上游源码提交和许可信息。包与框架分别分发；框架不捆绑可自动运行的内置包。

统一协议先定义实例创建与释放、会话创建与恢复、提交输入、取消、用户交互答复和事件订阅。事件覆盖文本增量、工具调用与结果、审批请求、用量、错误与结束状态。模型专用的数据允许通过有版本的扩展字段保留。

日志需要记录可重建模型输入的事实，包括工具定义、上下文变换、压缩和配置版本。包可以保留自己的内部状态格式，并提供向公共事件日志的映射；不强制所有包使用相同的消息数组或内部推理结构。

每个会话固定 Agent 包、版本和有效组合。切换包默认创建新会话；跨包续聊需要显式的状态转换器，不能直接把原始状态交给另一个包。新包可以获得导出的可读历史，但这不等同于原生状态恢复。

## 5. Codex 与 DeepSeek 包的制作路线

### Codex 能力包

目标是保留开源 Codex 中影响 Harness 能力的行为，并暴露可替换的模块入口。不能仅复制提示词，也不能把调用外部 Codex 进程视为完成源码级可编程能力。

当前已实现：包固定依赖官方 `@openai/codex@0.159.3`，使用官方 App Server stdio 接口接入会话、事件和取消，审批请求按原版协议拒绝扩权。用本地模拟服务驱动实际原版 Harness 验证工具、历史和失败路径，不要求付费模型凭据；`config.program` 指定的工作区代码可变换发给模型的输入。独立包的安装、凭据和配置说明见 `packs/codex/README.md`。这属于原版 Harness 的 App Server 边界适配与行为集成，不等于 Rust 内部循环及能力模块已经拆分或可以源码级任意替换。

后续仍需按固定上游提交分析执行循环、模型请求编码、工具流水线、上下文压缩、会话恢复、审批和子 Agent 的依赖关系。移除终端展示及产品入口等无关部分；通用宿主职责映射到本项目服务，Agent 特有的实现留在包内。按依赖图决定模块拆分，保留必要的原生组件。

Codex 的关键实现可能需要 Rust：候选方案为 TypeScript 组合层配合 Rust 能力模块，通过有版本的本地协议调用。完整引擎进程只提供粗粒度接口时，无法完成循环内部的模块替换；必须通过源码分析确定新增能力接口或局部移植的范围。性能、取消传播和状态一致性均需验证。

### DeepSeek 能力包

本地参考仓库的模型、工具、会话和执行循环本来就以 Cordis 插件组合。按用户最新要求，首个包保留官方原版 headless Harness，通过官方运行时依赖交付，包内适配层负责进程、事件投影和会话映射。用户 Cordis patch 在模型设置之后按顺序应用，可以装载和配置原版插件。后续再评估通用组合 SDK 的模块接口。

不直接把整个 DeepSeek 产品作为本项目宿主。是否复用其具体基础模块，在接口和依赖评估后决定；所有改造在本项目目录内进行，`Reference` 保持参考源码。

## 6. 阶段与验收

| 阶段 | 工作与产物 | 完成标准 |
| --- | --- | --- |
| P0：能力与依赖分析 | Codex/DeepSeek 能力矩阵、依赖图、可替换范围、上游版本、技术方案决策 | 分清可直接复用、需要桥接、需要移植的模块；明确行为一致性的比较范围 |
| P1：协议与 SDK | 包描述规范、生命周期、作用域、服务接口、事件、组合规则、状态版本设计 | 用两个无模型的测试包验证不同循环和状态结构均能接入，宿主不按包名分支；没有包时任务提交被拒绝，加载包后其能力生效 |
| P2：最小可编程运行时 | 组合内核、基础服务、命令行入口；模拟模型驱动的直接工具循环与可编程工具调用两种组合 | 用户代码可替换循环、工具、模型与上下文；两种工具呈现和调用方式均可运行与回放；停止、失败和卸载后无残留资源；验证不同包可在不修改宿主的情况下提供不同控制策略 |
| P3：首个真实能力包（DeepSeek） | 已实现官方 headless Harness 包、模型参数及有序 Cordis patch；mock Messages API 验证工具、恢复、取消和错误路径 | 真实包可独立安装并被宿主显式加载；源码级通用能力替换和真实 API 端到端仍待做 |
| P4：Codex 能力包 | 已实现固定官方依赖的 App Server stdio 适配包及 mock 测试；Rust 内部源码模块拆分/桥接和组合入口待做 | 已验证 App Server 边界集成，不将其记作 Rust loop 内任意模块替换；需完成上游行为比较和明确可替换模块 |
| P5：双包与分发 | 通用宿主支持显式加载多个包；增加双 fixture 路由、配置及状态隔离、卸载隔离测试；两个 workspace 均有独立 tarball 分发路径 | 框架与包可分别打包，基础双包运行路径已覆盖；完整安装锁定/检查/组合导出/升级回滚/教程，以及两个真实包端到端和实质源码级替换仍未完成 |

两个模拟包只用于早期验证协议。基础功能的最终验收必须包含两个真实能力包，并证明至少一次源码级能力替换，不能只做包选择器。

核心验证分为组合接口测试、生命周期与隔离测试、记录回放，以及少量真实模型端到端任务。与原版比较的是模型输入、工具语义、恢复和终止等 Harness 行为；模型输出存在随机性，不以字面相同作为标准。

## 7. 暂定技术与项目组织

候选技术：TypeScript 组合 SDK、Node.js 运行宿主、本地结构化事件协议；Codex 保留必要的 Rust 实现。优先评估 Cordis 作为组合内核，但先核实本地 DeepSeek 分支与上游的差异，再决定锁定依赖或维护小范围源码副本。

建议组织：

```text
Reference/              参考仓库
docs/                   计划、接口规范与架构决策
packages/kernel/        通用组合内核封装
packages/sdk/           包作者与用户编程接口
packages/runtime/       加载、实例、运行环境与交互
packages/capabilities/  可复用基础能力
packs/deepseek/         DeepSeek 能力包
packs/codex/            Codex 能力包与必要原生组件
apps/cli/               最小操作入口
examples/               用户组合与定制示例
tests/                  协议、回放与端到端验收
```

用户后续要求优先迁移前端、随后制作原版 DeepSeek Agent 包，因此已交付独立界面和首个真实运行包。上表仍是完整可编程框架的验收路线，不能据此将全部 P1–P5 标记为完成。插件商店、跨包原生状态迁移和运行中热替换暂不纳入首版交付。
