# t-alent：当前结构与后续计划

更新：2026-10-07。项目目标是让 t-alent 用可编程的 Agent 包定义另一个 Agent 的处理流程，并针对所选模型配置提示词和行为。模型与包独立选择；任务必须显式选择已加载的包和已配置的模型。

## 当前实现

- 网页与 Codex CLI 风格的终端界面共用加载器、模型注册表和任务协议。CLI 提供流式输出、取消、会话恢复、单次执行和 NDJSON；图标随所选包变化。
- 声明式包位于 `packs/<id>/`，每包只包含 `agent-package.json` 和 `prompts/`。Schema v1 使用有序提示词步骤、协议/供应商/型号条件和一个原生执行步骤定义处理逻辑。
- `packages/runtime/agent-compiler.mjs` 在加载时校验并计算内容指纹，将流程和提示词编译为 JSON IR。相同内容复用内存或磁盘缓存；内容和版本变化使缓存失效。任务只渲染已编译模板，不重复读取提示词文件。
- `packages/runtime/agent-program.mjs` 执行编译后的流程，调用 `packages/runtime/adapters/<id>/` 中固定版本的官方 Harness。原生适配器、依赖、测试和许可证统一由框架管理。
- 包版本与来源 Agent 版本分别记录；`agent-sources/<id>/<包版本>.json` 保存来源、固定版本和许可证证据。CLI 会话绑定包版本、来源版本和编译指纹。
- 打包脚本只分发 JSON 和提示词。网页产物写入 `dist/web/`，包归档写入 `dist/packages/`，两者独立构建。

当前已接入包由原生适配器注册表统一管理，完整列表与后续候选见 [Agent 接入清单](AGENT-CATALOG.md)。模型协议、来源和运行边界见 [Harness 报告](HARNESSES.md) 与 [来源版本记录](../agent-sources/README.md)。兼容协议与定制提示词提供模型适配能力，实际工具调用和推理效果仍需针对具体模型验证。

## 后续工作

1. **扩展处理逻辑。** 在保持 JSON + prompts 结构的前提下，按需求增加有版本的流程操作、结果校验与终止策略。新增操作必须明确资源限制、缓存失效规则和错误行为。
2. **原生能力模块替换。** 评估各官方 Harness 的循环、上下文、工具和状态接口，再确定可替换模块。现有 SDK/CLI 边界适配以及提示词流程不表示 Codex Rust 内部模块已经拆分；早期 `harness.ts` 组合 SDK 仍是研究方向。
3. **模型适配验收。** 用各协议的本地模拟服务保持工具、历史、取消和失败路径可复现；在用户配置真实凭据后，再验证指定模型的行为与效果。
4. **跨包状态转换。** 若需要跨包续聊，增加显式的历史导出和状态转换器。不同 Harness 的原生会话格式不能直接互换。

## 维护与验证

`npm run build` 检查前端类型并构建网页，类型检查拒绝未使用的局部声明与参数。`npm test` 覆盖宿主、编译器、CLI 和原生适配器；宿主集成测试需要允许本机回环监听。`npm run pack:agents` 和 `npm run verify:agents` 验证包分发结构及来源版本。性能测量使用 `npm run bench:agents`。

参考源码保存在本地 `Reference/`，不作为应用依赖。`.talent/` 包含会话、缓存及本地运行时；维护时不要将这些用户状态当作无用源码删除。

详细使用和编写说明见 [CLI 指南](CLI.md)、[Agent 包指南](AGENT-PACKAGES.md)、[前端来源说明](../apps/web/MIGRATION.md) 和 [项目说明](../项目说明.md)。
